The Story

Curiosity is a competitive advantage.

I'm a Computer Science undergraduate at Shri Ramswaroop Memorial University who'd rather ship something than talk about shipping it. From an unbeatable Tic-Tac-Toe AI built with Minimax pruning to a full-stack image-captioning platform running Hugging Face models in production, the pattern stays the same: pick a hard problem, learn whatever it demands, and don't stop until it works.

  • 01

    Ship before it's perfect

    A working prototype teaches you more than a week of planning. I'd rather deploy something rough and fix it in the open than polish something no one's used yet.

  • 02

    Debug relentlessly

    Every crash is a clue. I traced a memory-constrained backend failure down to a 512MB free-tier limit and rebuilt the inference pipeline around it instead of walking away.

  • 03

    Security is not optional

    Shipping fast doesn't mean shipping careless. I've remediated a critical RCE vulnerability in production — the kind of fix that never shows up in a demo but matters most.

  • 04

    Learn in public, build alone

    I taught myself the stack for every project I've shipped — React, FastAPI, Docker, LLM APIs — and built each one solo, start to finish, while keeping up with coursework.
